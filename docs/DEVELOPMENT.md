# Development

## Layout

```text
src/                    Current plugin source and embedded resources
assets/                 Coach portraits and sprite sheets
docs/screenshots/       Cropped, authentic coach UI captures
test/review/            Offline regression harness
coach_system_prompt.txt Editable prompt template
build-plugin.ps1        Immutable versioned builds
deploy-plugin.ps1       Explicit DLL deployment while FM is closed
```

`ref/`, `interop/`, `builds/`, `dist/`, runtime snapshots and credentials are local-only and excluded by `.gitignore`.

## Local dependencies

Use PowerShell, an installed .NET SDK, and the .NET 6 runtime used by the loader. The build script invokes the SDK's C# compiler directly and references that runtime; it does not need NuGet or .NET 6 targeting packs.

Supply these references locally:

- `ref/BepInEx.Core.dll`
- `ref/BepInEx.Unity.IL2CPP.dll`
- `ref/Il2CppInterop.Runtime.dll`
- `ref/Il2CppInterop.Common.dll`
- `interop/*.dll` generated by your compatible FM27/BepInEx installation, including `SI.Input.dll`.

The generated interop assemblies must match the installed game. Do not publish them with the project. The tested local reference folder contains additional loader dependencies; the compiler reads managed DLLs from both reference directories.

## Build

```powershell
.\build-plugin.ps1
```

Output: `builds/v<version>/<timestamp>/FMCoach.dll` and `build.json`. The manifest records the DLL hash, version and source hashes. A build neither installs the plugin nor opens FM. Existing candidate directories are never overwritten.

Keep the version in `src/Plugin.cs` aligned with `src/FMCoach.csproj`; the builder rejects a mismatch. The project also supports normal `dotnet build` when the appropriate targeting packs and references are installed, but the script is the verified local build path.

## Test

```powershell
.\test\review\Run-Regression.ps1
```

The runner compiles the complete current source and then exercises production components with binding, clock and HTTP substitutes. It does not read an API key or contact OpenRouter. Generated assemblies and response files go in `test/review/out/`.

The former legacy source tree and development-run artifacts were removed during publication cleanup. The current suite contains 169 checks; the earlier two-tree total of 337 included 168 checks against the retired source.

## Deploy

Save and close FM, then pass the exact candidate path:

```powershell
.\deploy-plugin.ps1 -DllPath .\builds\v0.7.30\<timestamp>\FMCoach.dll
```

The helper targets the default Steam FM27 installation, verifies the assembly identity, checks that FM is closed, and verifies the installed SHA-256. For another installation location, copy the DLL manually into that installation's `BepInEx/plugins/FMCoach/` directory while FM is closed.

## Local configuration

BepInEx generates `BepInEx/config/local.fmcoach.poc.cfg`. The `[AI]` section contains `KeyFile`, `Model`, `MaxTokens`, `TimeoutSeconds`, `PromptFile` and `TestDir`. Use an absolute key-file path. `TestDir` contains runtime chat hooks and snapshots and must stay private.

Keep the editable root prompt and `src/coach_system_prompt.txt` synchronized when changing default behaviour. The embedded prompt is the fallback when the configured editable file is missing or empty.

Experimental inactive-slot selector diagnostics are off by default (`[Debug] SlotProviderProbes = false`). Tested selectors did not return inactive plans; do not relax ownership or freshness checks to make coverage appear complete.
